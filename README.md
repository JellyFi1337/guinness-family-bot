# Guinness Family Discord Bot

Guinness Bot — многофункциональный Discord-бот для автоматизации работы игрового сообщества: обработки заявок и тикетов, организации событий, управления казной и автопарком, временными голосовыми комнатами, внутренней валютой, рекрутингом и серверной статистикой.

Проект написан на Python с использованием `discord.py`, PostgreSQL 18, асинхронного драйвера Psycopg 3 и Discord Components v2. Интерфейсы построены на `LayoutView`, `Container`, `Section`, `TextDisplay`, `MediaGallery` и `ActionRow`: текст, изображения и элементы управления образуют единые современные карточки, а постоянные `custom_id` сохраняют работоспособность кнопок после перезапуска.

## Архитектура и хранение данных

Код разделён по ответственности. Обработчики Discord не должны напрямую решать задачи хранения и восстановления состояния: Cog принимает взаимодействие, сервис координирует сценарий, репозиторий выполняет SQL, а инфраструктурный слой управляет соединениями и схемой.

```text
Discord API
    │
    ├── ui/             Components v2 и единый транспорт сообщений
    └── cogs/           команды, события, формы и проверки доступа
            │
        services/       сценарии, согласование Discord ↔ PostgreSQL, фоновые задачи
            │
       repositories/    изолированные запросы и модели хранения
            │
      infrastructure/   пул PostgreSQL, SQL-совместимость и миграции
```

Рабочая база задаётся переменной `DATABASE_URL`. На сервере бот подключается к PostgreSQL через `127.0.0.1:5432`, а из Windows/PyCharm — к той же базе через SSH-туннель. Systemd-unit требует PostgreSQL и не позволяет незаметно запуститься с локальным SQLite-файлом. В базе хранятся счётчики заявок, настройки статичных сообщений, казна и транзакции, сборы, комнаты, бронирования, статистика, валюта, роли, розыгрыши и рекрутинг.

При запуске применяются только ещё не выполненные версионные миграции. Их checksum защищает историю схемы от незаметного изменения. PostgreSQL необходимо регулярно резервировать через `pg_dump`; локальный SQLite fallback по-прежнему создаёт снимки перед изменением схемы. Резервная копия БД не заменяет копии `.env`, `bot_config.toml` и `SHOWDOWN_STATE_PATH`.

### Components v2

Все исходящие сообщения проходят через единый слой `ui/messages.py`. Он переводит содержимое в нативный Components v2 layout и корректно обрабатывает первоначальные ответы, follow-up и редактирование отложенного ответа. Общий визуальный стандарт включает:

- акцентный цвет контейнера по предметной области (`Accent` из `ui/design.py`);
- упоминания, краткий контекст и поля внутри одного основного `Container`;
- заголовки и поля в `TextDisplay`, превью только с URL Discord (`Section`/`Thumbnail`);
- управляющие `ActionRow` внизу той же карточки и их отключение после завершения сценария;
- контролируемое сокращение текста при достижении лимита Components v2.

Слой совместимости переносит существующие постоянные кнопки в новый layout без изменения их `custom_id`. Новые интерфейсы следует создавать непосредственно через `LayoutView`; отправлять сообщения напрямую через `channel.send`, `response.send_message` или `message.edit` вне `ui/messages.py` не следует.

## Эксплуатационные гарантии

### Согласованность Discord и PostgreSQL

Discord API и PostgreSQL не поддерживают общую транзакцию, поэтому критические многошаговые сценарии используют явное состояние операции:

- `operation_outbox` сохраняет намерение до вызова Discord и повторяет незавершённую операцию после временной ошибки или перезапуска;
- каждая операция имеет `idempotency_key`, lease на обработку, число попыток и состояния `pending`, `processing`, `retry`, `completed` либо `dead`;
- повтор обрабатывается с экспоненциальной задержкой и jitter, а внешний Discord ID фиксируется после успеха;
- `command_receipts` защищают поддерживаемые денежные команды от двойного применения одного interaction;
- согласование купленной роли сначала сохраняет Discord role ID, поэтому восстановление не создаёт вторую роль и не выполняет ошибочный возврат средств;
- продажа косметической роли резервируется вместе с outbox-задачей: после перезапуска бот завершает удаление роли и начисляет возврат 50% ровно один раз;
- отказ по кастомной роли атомарно сохраняет возврат и задачу представления решения, поэтому карточка, личное уведомление и СС-лог восстанавливаются после сбоя;
- победители завершённого розыгрыша фиксируются до публикации результата, поэтому повторная доставка не меняет выбор.

Постоянные панели имеют ключ `(guild_id, panel_key)`. Сервис использует lock на конкретную панель, ищет сообщение по сохранённому ID и скрытому marker, а историю читает только при потере канонического сообщения. Хеш payload исключает неизменившиеся Discord edits. Поэтому повторный `/admin setup`, очистка настроек или перезапуск не должны создавать вторую панель.

### PostgreSQL под нагрузкой

В рабочем режиме используется ограниченный асинхронный пул Psycopg 3. PostgreSQL обслуживает Windows-разработку и серверный процесс через одну централизованную базу, поддерживает параллельные чтения, серверные ограничения и надёжное восстановление. Старые критические секции `BEGIN IMMEDIATE` отображаются на transaction-scoped advisory lock, сохраняя атомарность SQLite-сценариев во время постепенного перевода запросов на точечные row locks.

Размер пула задаёт `DB_POOL_SIZE`. Для одного экземпляра бота обычно достаточно значения `4`; увеличение имеет смысл только после измерений и с учётом `max_connections` PostgreSQL. База допускает несколько клиентов администрирования, но два экземпляра Discord-бота с одним token одновременно запускать нельзя.

### Статистика и срок хранения

События статистики поступают в ограниченную асинхронную очередь и записываются пачками. Настройки `STATS_QUEUE_SIZE` и `STATS_FLUSH_BATCH_SIZE` позволяют согласовать всплески Discord-событий со скоростью базы. Событие удаления, пришедшее раньше события создания сообщения, сохраняется как tombstone и применяется после записи исходного события.

Сырые сообщения, голосовые сессии, входы/выходы и действия периодически сворачиваются в суточные таблицы. Сырые данные по умолчанию хранятся 90 дней, суточные агрегаты — 730 дней. Открытые голосовые сессии не удаляются, а интервалы, пересекающие полночь, распределяются по соответствующим дням. Периодическое обслуживание обновляет статистику планировщика PostgreSQL через `ANALYZE`.

### Фоновые задачи

`TaskSupervisor` владеет периодическими задачами автопарка, магазина, розыгрышей, рекрутинга, статистики и outbox. Для каждой задачи применяются таймаут, экспоненциальный backoff с jitter и автоматическое продолжение после ошибки. Состояние `healthy`/`degraded`, время последнего успеха, длительность и текст последней ошибки сохраняются в `task_health`; частота heartbeat задаётся `TASK_HEALTH_HEARTBEAT_SECONDS`.

Режим обслуживания приостанавливает запуск новых фоновых итераций и дожидается уже выполняющихся. При штатном завершении supervisor отменяет принадлежащие ему задачи, затем закрываются Discord-клиент и PostgreSQL-пул.

## Требования

- Python 3.12 или новее;
- Discord-приложение и bot token;
- включённый privileged intent `Server Members Intent`; `Message Content Intent`
  не требуется, поскольку управление выполняется slash-командами и компонентами;
- PostgreSQL 18 на рабочем сервере;
- зафиксированные зависимости из `requirements.lock`;
- установленный `ffmpeg` для музыкального воспроизведения.

Для полного функционала роли бота в Discord требуются:

- просмотр каналов, отправка форматированных сообщений и файлов;
- чтение истории сообщений;
- создание и управление ветками;
- управление каналами и правами доступа;
- управление ролями — роль бота должна находиться выше управляемых ролей;
- перемещение участников между голосовыми каналами;
- подключение и передача голоса (`Connect` и `Speak`) для музыкального бота;
- создание приглашений и `Manage Server` для учёта использованной ссылки;
- управление сообщениями для очистки и служебных сценариев.

Администраторские права упрощают установку. В рабочей среде можно выдать только перечисленные разрешения.

## Установка и первый запуск

### 1. Создание окружения

```bash
python -m venv .venv
```

Windows PowerShell:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install --require-hashes -r requirements.lock
```

Linux:

```bash
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install --require-hashes -r requirements.lock
```

### 2. Конфигурация

Скопируйте секретный шаблон и заполните `TOKEN` и `DATABASE_URL`:

```bash
cp .env.example .env
```

На Windows файл можно скопировать через проводник или командой:

```powershell
Copy-Item .env.example .env
```

Все несекретные параметры каналов, ролей и экономики находятся в `bot_config.toml`.
Discord identity (`BOT_PROFILE`, `TOKEN_*`, `GUILD_ID_*`, `BOT_OWNER_ID`,
`COMMAND_SYNC_FORCE`, `COMMAND_CLEAR_GLOBAL`) задаётся **только в `.env`**.
ID каналов и категорий в TOML имеет приоритет над именем; имя — резервный поиск.
На Linux ограничьте доступ:

```bash
chmod 600 .env
```

### 3. Запуск

```bash
python main.py
```

`GUILD_ID` (через `GUILD_ID_TEST` / `GUILD_ID_MAIN` + `BOT_PROFILE` в `.env`) обязателен: команды синхронизируются только с выбранным сервером и появляются почти сразу. Бот отклоняет взаимодействия с других серверов и автоматически покидает их. Схема команд кэшируется: повторный запуск без изменений не выполняет bulk PUT и не расходует лимит Discord. Для одноразового удаления старых глобальных команд установите в `.env` `COMMAND_CLEAR_GLOBAL=true`, запустите бота и затем верните `false`. `COMMAND_SYNC_FORCE=true` принудительно обновляет схему и также должен использоваться только для одного запуска.

### 4. Создание постоянных сообщений

После запуска выполните:

```text
/admin setup
```

Команда создаёт либо обновляет панели заявок, ролей, дней рождения, казны, автопарка, еженедельной статистики и магазина. Повторный запуск безопасен: сервис использует guild-scoped ID и marker панели, восстанавливает привязку после очистки БД и удаляет найденные дубликаты только после успешного обновления канонического сообщения.

## Настройка Discord

Рекомендуемая структура Memphis (мастер `/setup start` предлагает её при создании каналов): публичные `старт-и-правила`, `мои-задачи`, `события`, `отчёты`, `помощь`; закрытые `очередь-сс`, `выплаты`, `снабжение`, `аудит`. Живые ключи конфигурации не переименовываются: привязка идёт по Discord ID. Личная панель участника — `/me` (вкладки «Мои задачи», «События», «Сдать отчёт», «Ресурсы», «Мой прогресс», «Помощь»). Панель старшего состава — `/staff panel`.

Критически важные маршруты:

| Назначение | Значение по умолчанию |
| --- | --- |
| заявки в семью | `🐳・заявки-в-семью` |
| старт и правила | `старт-и-правила` |
| очередь старшего состава | `очередь-сс` |
| аудит | `аудит` |
| помощь | `помощь`, результат `🛟・help` |
| казна и транзакции | `выплаты`, `💱・транзакции` |
| события и отчёты | `события`, `отчёты`; архив старых сборов — `архив-сборов` |
| голосовые комнаты | категория `✨・VOICES・✨`, lobby `🌠・Create Voice +` |
| снабжение | `снабжение`, журнал `🚗・авто-логи` |
| статистика | `📢・новости` |
| рекрутинг | `💼・рекрутинг`, `📎・рекрутинг-логи` |

## Функциональные подсистемы

### Постоянные панели и формы

`/admin setup` подготавливает следующие интерфейсы:

- «Нужна помощь» — текст запроса и до пяти изображений; сообщение публикуется в канале Help с упоминанием роли Help и отдельной веткой для обсуждения;
- «Обращение к старшему составу» — жалоба, предложение, Owner-request, обращение по работе бота или анонимный запрос;
- «Заявка в боевую команду» — IC-имя и описание опыта;
- «Заявка в семью» — OOC-данные, IC-имя, IC-паспорт, мотивация и готовность сменить фамилию;
- «Добавить день рождения» — заявка на дату в формате `ДД.ММ`;
- «Роли» — Guest, Help и Contract с повторным снятием, а также запросы
  Young/Main/Friend/Super Friend;
- магазин, казна, автопарк и список дней рождения.

Заявки, поступающие в категорию старшего состава, могут обрабатывать только роли из `HIGH_TOOLS_ALLOWED_ROLES` или `HIGH_TOOLS_ALLOWED_ROLE_IDS`. При создании нового запроса упоминаются роли из `REQUEST_PING_ROLES`. Одобренные и отклонённые сообщения получают статус и информацию о проверившем сотруднике. Причина отклонения выбирается из настраиваемого списка и отправляется заявителю в личные сообщения.

Роль Help общедоступна. Contract выдаётся только участникам с Young, Main,
Senior Staff, High или Owner. Young/Main и Friend/Super Friend оформляются через
согласование. Для каждой пары проверяющий может выбрать итоговый уровень,
независимо от выбранного заявителем варианта.

### Обращения и тикеты

Обычные жалобы и предложения создают приватный канал вида `тип-username-0001`.
Owner-request видят только автор, роль Owner и Discord-администраторы. Обращение
по работе бота доступно автору, Discord-администраторам и настроенному владельцу
бота; отсутствие владельца на сервере не мешает создать тикет. В тикете доступны:

- «Взять тикет» / «Сняться с тикета» — одна динамическая кнопка;
- «Назначить на тикет» — выбор сотрудника старшего состава;
- «Закрыть тикет» — автор или старший состав.

Назначения отображаются в карточке тикета, отдельным Components v2-событием в
канале и в журнале СС. Иерархия
`TICKET_ASSIGNMENT_ROLE_HIERARCHY` задаётся сверху вниз: сотрудник не может
назначить пользователя с более высокой учитываемой ролью. О новом неанонимном
тикете публикуется уведомление со ссылкой.

Анонимное обращение не создаёт тикет: обезличенная версия публикуется отдельно,
а автор сохраняется только в закрытом журнале. Кнопка ответа доступна в
публичной карточке и в созданной под ней ветке. Ответ сотрудника приходит автору
в ЛС, а ответ автора возвращается в эту ветку без раскрытия его личности.
`🕵・анон-логи` хранит только закрытый аудит автора исходного обращения; все
сообщения переписки связаны с номером обращения и
продолжают работать после перезапуска.

### Казна

В `🏛️・казна` хранится единственное обновляемое сообщение с балансом и последними операциями. Кнопки «Пополнение» и «Снятие» открывают форму транзакции. Все операции публикуются отдельными Components v2-карточками в `💱・транзакции`.

`/admin treasury_set` устанавливает абсолютное значение и фиксирует старое значение, новое значение и разницу. Команда ограничена ролью владельца казны. `/admin transaction_add` выполняет обычное пополнение или списание и не создаёт копию статичного сообщения казны.

### Заявки и роли

- семейная заявка одобряется с выдачей Young или Main;
- проверяющий может запросить у автора семейной заявки ник формата
  `Имя в игре | Имя в реале`; автор подтверждает изменение кнопкой в ЛС,
  статус заявки и СС-логи обновляются, а проверяющий получает личное уведомление;
- заявка в боевую команду выдаёт боевую роль сервера; приоритетные роли прошлого проекта на допуск не влияют;
- день рождения после одобрения попадает в общий обновляемый календарь;
- роли Young/Main и Friend/Super Friend выдаются после согласования;
- все решения записываются в `📩・сс-логи` единообразными Components v2-карточками.

### Сборы и контракты

`/summit list_create` создаёт общий список в `🏟️・сборы-мп` и сразу открывает под ним ветку для общения. Участник может вступить или выйти, а инициатор/администрация — закрыть вход, запустить либо удалить список. При запуске бот публикует участников над карточкой и отключает кнопки. Функционал замен в обычных списках не используется.

`/summit contract_create` работает аналогично в `💸・контракты`, упоминает роль
Contract над сообщением и сразу создаёт под ним ветку для общения. При удалении
остаётся карточка с названием, создателем и пользователем, выполнившим удаление.

VIP-эмодзи участника, приобретённый в магазине, отображается в обычных списках и контрактах.

Команды боевого сбора удалены. Открытые записи закрываются при старте: состав сохраняется, кнопки отвечают, что сбор архивирован. Новые события — `/event create`, контракты каталога — `/contract start`.

### Временные голосовые комнаты

При входе в `🌠・Create Voice +` бот создаёт персональную голосовую комнату, переносит участника и публикует панель управления в чате голосового канала. Один участник не может владеть несколькими комнатами: повторный вход возвращает его в уже существующую.

Владелец сохраняется до удаления комнаты, даже если временно вышел. Только владелец использует кнопки и команды. Панель позволяет:

- закрыть/открыть подключение;
- скрыть/показать канал;
- установить лимит;
- отключить участника;
- выдать доступ роли или отдельному участнику;
- переименовать или удалить комнату;
- передать право владения.

Постоянный персональный ban-лист доступен только при активном VIP. Он хранится за владельцем и применяется к его новым комнатам. При передаче владения применяется ban-лист нового владельца. Пустая комната удаляется автоматически.

### Автопарк

В `🅿️・автопарк` находится одно обновляемое сообщение со списком машин, номером, принадлежностью и текущей бронью. Пользователь выбирает свободную машину, вводит IC-имя и срок (`21:30`, `2ч`, `90м`, максимум семь дней). Свои брони можно отменять через кнопку.

Администратор может принудительно завершить активную бронь через
`/car booking_cancel`; пользователь и причина сохраняются в журнале. Добавление,
редактирование, удаление, бронирование и отмена публикуются Components
v2-карточками в `🚗・авто-логи`. Истёкшие брони освобождаются автоматически, а
список обновляется раз в минуту.

### Еженедельная статистика

Бот собирает данные с начала текущей недели по московскому времени:

- общее число участников, входы и выходы;
- отправленные и удалённые сообщения, число активных авторов;
- текстовые и голосовые каналы-лидеры, включая сохранённые названия удалённых каналов;
- суммарное голосовое время и пик одновременной активности;
- топ-5 участников по сообщениям и голосу;
- создатели уже удалённых временных комнат и суммарное время участников в их комнатах;
- созданные за неделю каналы;
- закрытые тикеты, одобренные и отклонённые заявки;
- лидеры по запущенным контрактам, обычным сборам и архивным сборам;
- среднее число сообщений в день.

В рейтинги каналов входят только разделы, которые доступны настроенной роли
`Main`. Закрытые тикеты, служебные и административные каналы в списках каналов
не показываются. Сообщения их участников при этом продолжают учитываться в
личном рейтинге общей активности. Для удалённых доступных каналов сохраняются
название и накопленная активность.
Удалённые временные комнаты сводятся по их первоначальному создателю: отчёт
показывает число комнат и общее время, проведённое участниками. Передача комнаты
не меняет автора для этой статистики. AFK-канал исключается по имени или ID.
Открытые voice-сессии фиксируются heartbeat-механизмом, поэтому аварийный
перезапуск не раздувает длительность. Для каждой недели публикуется отдельное
сообщение: текущий отчёт обновляется каждые пять минут, а после завершения недели
фиксируется и больше не изменяется. Новая неделя получает новое сообщение.
`/stats weekly` возвращает приватную копию текущего отчёта, `/stats update`
запускает ручное обновление.

Отдельно менеджер статуса получает онлайн игрового сервера из RAGE MP
master-list. Каждая успешная выборка обновляет компактный дневной агрегат:
минимум, среднее, последнее значение и пик. `/stats server_online` показывает
эти значения по дням и неделям. Подпись берётся из профиля и привязки
источника онлайна, а не из ключей предыдущего проекта.

### Guinn Coins, магазин и VIP

Guinn Coins — внутренняя валюта сервера. Пользователям доступны ежедневная награда, переводы, таблица лидеров и покупки:

- цветная роль `🪙 Цвет` с выбранным HEX;
- кастомная роль `🪙 Название`;
- VIP на неделю или месяц;
- VIP-эмодзи для списков;
- продажа купленной роли с возвратом 50%.

Название кастомной роли сначала отправляется в `role-approval`. Старший состав выбирает причину при отказе; пользователю возвращается 50% стоимости и приходит личное сообщение. При одобрении роль создаётся и располагается выше цветной роли.

Без VIP разрешена одна цветная и одна кастомная роль. С VIP можно иметь до трёх купленных ролей и менять их порядок командой `/coins role_order`. Если выбранный HEX уже используется другой купленной цветной ролью, бот выдаёт существующую Discord-роль вместо создания копии. При продаже она снимается только с продавца и удаляется после ухода последнего владельца. Градиент применяется только при наличии Discord-функции `ENHANCED_ROLE_COLORS` на сервере.

После окончания VIP купленные роли удаляются с возвратом 50%, VIP снимается, постоянный voice ban-лист очищается, а интерфейсы списков обновляются. Если владелец кастомной роли покидает сервер, его кастомная роль удаляется.

### Музыка за Guinn Coins

`/music play` принимает название либо ссылку с разрешённого домена. Метаданные
извлекаются через `yt-dlp` до списания: live-трансляции, плейлисты, неизвестная
длительность, слишком длинные записи и внутренние/неразрешённые URL отклоняются.
Трек до 10 минут по умолчанию стоит 500 Coins, более длинный — 1000 Coins.
Все slash-команды `/music` работают только в текстовом чате голосового канала.
Для заказа песни пользователь должен находиться в этом же voice-канале.

В текстовом канале используется одно сообщение плеера. Оно редактируется при
добавлении и смене песен, показывает прогресс, заказчика, цену, громкость, режим
повтора и ближайшие позиции очереди. Плеер не создаёт по сообщению на каждый
трек; после штатного отключения его сообщение удаляется.
При длительном бездействии бот освобождает голосовое соединение, но оставляет
каноническую панель и возобновляет сессию при следующем заказе.

Очередь ограничена глобально и отдельно для каждого пользователя. `/music skip`
создаёт голосование только среди присутствующих в канале слушателей; старший
состав пропускает сразу. Автор может бесплатно убрать ожидающий заказ или
отменить ошибочный текущий трек через `/music cancel` в течение настраиваемого
окна. При раннем skip чужого заказа стоимость возвращается, а поздний skip
остаётся без возврата для защиты от бесплатного прослушивания почти целого
трека.

`/music mode` предлагает три режима: без повтора, повтор текущего трека и цикл
очереди. Режимы доступны и кнопками плеера; повторное воспроизведение уже
оплаченного трека не создаёт новое списание. Там же доступны очередь,
пауза/продолжение, регулировка громкости и отключение. `/music disconnect`
доступна старшему составу: она останавливает сессию, возвращает незавершённые
заказы, очищает очередь, отключает бота и удаляет плеер.

Списание, постановка в очередь, состояние воспроизведения и возврат сохраняются
в PostgreSQL. После аварии или перезапуска все незавершённые заказы возвращаются
ровно один раз. `/music stats` показывает старшему составу оборот, возвраты и
лидеров заказов.

### Розыгрыши и опросы

`/giveaway create` создаёт розыгрыш с акцентным оформлением события в настроенном канале либо в текущем текстовом канале, если специальный канал не найден. Поддерживаются вступление/выход, срок до 30 дней, от 1 до 20 победителей, автоматическое завершение, принудительное завершение, удаление, повторный выбор победителей и ветка обсуждения. Выбор выполняется через криптографически стойкий `SystemRandom`.

`/poll create` создаёт Components v2-опрос в канале или ветке вызова. Варианты передаются через `|`, допускается 2–10 вариантов, множественный выбор, срок до 168 часов и анонимное отображение инициатора. Компонентная реализация сохраняет голоса в PostgreSQL и остаётся совместимой с единым визуальным слоем; нативный Discord Poll не используется, поскольку он несовместим с Components v2 в одном сообщении.

### Рекрутинг

Для каждого участника с ролью из `RECRUITING_ROLES` бот создаёт бессрочное персональное приглашение и отправляет его в ЛС. При входе бот определяет использованную ссылку и сохраняет рекрутера. Результат засчитывается только когда приглашённый участник подал семейную заявку и она была одобрена.

В `💼・рекрутинг` поддерживается единый отчёт: входы, заявки, принятые, отклонённые, конверсия, показатели каждого рекрутера и топы за 7 дней, 30 дней и всё время. Подача и решение по заявке логируются в `📎・рекрутинг-логи`. Панель отчёта также создаётся или восстанавливается командой `/admin setup`.

При снятии роли рекрутера или выходе сотрудника его ссылка отзывается. Для неоднозначных случаев одновременного входа предусмотрена ручная административная привязка `/recruiting assign`.

### Сборы на дни рождения

`/fundraiser create` создаёт закрытый канал в категории `🎂・BIRTHDAY SECRET・🎂`. Роли Owner, Dep. Owner, High, Main и Young получают доступ и упоминаются над первым сообщением, а виновник торжества канал не видит. Карточка сбора оформляется акцентным цветом участника, без вложения. Участники добавляют взносы кнопкой, сумма и список автоматически обновляются. Администратор может удалить ошибочную запись.

### Private Showdown

`/showdown toggle` доступна только настроенному владельцу бота и переключает режим
закрытого тестирования:

- создаёт роль `Private Showdown` и канал `#private-showdown` в категории `⚙️・DEVELOPER・⚙️`;
- атомарно сохраняет снимок доступных боту ролей в отдельном JSON-файле;
- снимает сохранённые роли со всех пользователей, кроме ботов;
- выдаёт роль Showdown и скрывает от неё остальные каналы;
- запрещает пользователям писать в тестовый канал;
- повторный вызов сначала восстанавливает роли, затем снимает ограничения и удаляет канал.

Снимок задаётся через `SHOWDOWN_STATE_PATH` и переживает перезапуск процесса.
Если восстановить часть ролей не удалось, режим остаётся включённым для
безопасной повторной попытки. Файл снимка необходимо резервировать вместе с
PostgreSQL.

## Конфигурация

Секреты и Discord identity находятся в игнорируемом Git-файле `.env`
(`TOKEN_*`, `DATABASE_URL`, `BOT_PROFILE`, `GUILD_ID_*`, `BOT_OWNER_ID`,
`COMMAND_*`). Обычные настройки каналов, ролей и экономики — в
версионируемом `bot_config.toml`. Ключ канала или роли в `.env` остановит
запуск с понятной ошибкой; `GUILD_ID` / `BOT_OWNER_ID` в TOML тоже запрещены.

Основные правила:

1. `TOKEN` и пароль внутри `DATABASE_URL` никогда не публикуйте и не добавляйте `.env` в Git.
2. `GUILD_ID_TEST` / `GUILD_ID_MAIN` в `.env` (с `BOT_PROFILE`) обязательны и задают единственный разрешённый сервер.
3. `BOT_OWNER_ID` в `.env` обязателен и даёт указанному владельцу доступ ко всем slash-командам и компонентам независимо от ролей, `Administrator`, технического режима и cooldown. Проверки данных, баланса и принадлежности объектов сохраняются.
4. Для маршрутов задавайте одновременно понятное имя и стабильный ID. Если ID заполнен, он используется первым.
5. В списках ролей имена разделяются запятыми, причины отказа — символом `|`.
6. Карта добавляется командой `/event map_add` (название, тип события, версия, источник). Каталог не ограничен 25 записями; Discord Select листает страницы.
7. После изменения `.env` или `bot_config.toml` перезапустите процесс бота; экономические ставки также можно менять без перезапуска через `/stats economy_config`.

Музыкальные параметры `MUSIC_PRICE_*`, лимиты очереди, окно отмены, порог
голосования, разрешённые домены и путь `FFMPEG_EXECUTABLE` находятся в
`bot_config.toml`. Изменения этих значений применяются после перезапуска.

### PostgreSQL, статистика и фоновые задачи

| Переменная | По умолчанию | Допустимый диапазон | Назначение |
| --- | ---: | ---: | --- |
| `DATABASE_URL` (`.env`) | — | URL | подключение `postgresql://user:password@host:port/database` |
| `DATABASE_REQUIRE_POSTGRES` (systemd) | `false` | boolean | запретить тестовый SQLite fallback; unit задаёт `true` |
| `DB_POOL_SIZE` (`bot_config.toml`) | `4` | 1–32 | максимальный размер пула PostgreSQL |
| `STATS_QUEUE_SIZE` | `50000` | 5000–250000 | вместимость очереди событий статистики при всплеске нагрузки |
| `STATS_FLUSH_BATCH_SIZE` | `2000` | 100–10000 | максимальное число событий в одной пакетной записи |
| `STATS_RAW_RETENTION_DAYS` | `90` | 14–365 | срок хранения детализированных событий |
| `STATS_AGGREGATE_RETENTION_DAYS` | `730` | 90–3650 | срок хранения суточных агрегатов |
| `TASK_HEALTH_HEARTBEAT_SECONDS` | `60` | 15–600 | период обновления успешного состояния фоновых задач |

Значения вне диапазона автоматически ограничиваются ближайшей допустимой границей. При настройке под нагрузку сначала увеличивайте размер пачки, затем очередь; размер PostgreSQL-пула меняйте только по результатам наблюдения за задержками, числом активных соединений и ресурсами VPS.

### Статус бота

- `BOT_STATUS`: `online`, `idle`, `dnd`, `invisible`;
- `BOT_ACTIVITY_TYPE`: `playing`, `watching`, `listening`, `competing`, `streaming`, `custom`, `none`;
- `BOT_ACTIVITY_TEXT`: постоянный текст;
- `BOT_ACTIVITY_TEXTS`: ротация значений через `|`, имеет приоритет над одиночным текстом;
- `BOT_ACTIVITY_INTERVAL`: интервал ротации, минимум 15 секунд;
- `BOT_STREAM_URL`: URL для типа `streaming`.

Шаблоны обычной активности: `{users}`, `{guilds}`, `{latency}`. Живой статус
игрового сервера включается профилем `online_source`. Архивный master-list RAGE
остаётся в коде и читает `rage_server_query` / `rage_server_name` в `[profile]`;
устаревшие ключи предыдущего проекта ещё принимаются с предупреждением в логе.
Активный Memphis по умолчанию источник не опрашивает.
Шаблон поддерживает `{server}`, `{players}` и `{players_word}`.
Последнее успешное значение сохраняется при временном сбое API; успешные
выборки записываются в дневную статистику.

## Развёртывание на Ubuntu

Основные команды после установки:

```bash
sudo systemctl status guinnes-bot.service
```

Не запускайте рабочий экземпляр одновременно вручную и через systemd: два процесса будут конкурировать за одну Discord-сессию. Подключение PyCharm и служебных клиентов к PostgreSQL при этом допустимо.

### Диагностика типовых проблем

- Команда не появилась — проверьте `GUILD_ID`, журнал строки `Synced ... commands` и перезапустите бота.
- Канал не найден — заполните соответствующий `*_ID`; имя с emoji и пробелами должно совпадать полностью.
- Бот не выдаёт роль — переместите роль бота выше целевой роли и выдайте `Manage Roles`.
- Не создаётся voice-комната — проверьте ID lobby, категорию, `Manage Channels` и `Move Members`.
- Музыка не запускается — проверьте `ffmpeg -version`, наличие `yt-dlp` через `pip check` и права `Connect`/`Speak`.
- Не определяется рекрутинговая ссылка — выдайте `Manage Server` и `Create Invite`; для пропущенного случая используйте `/recruiting assign`.
- Кнопка старого сообщения не работает после обновления — выполните `/admin setup`; постоянные панели будут найдены по ID или marker и обновлены до Components v2.

## Безопасность

- файл `.env` должен быть доступен только пользователю сервиса и никогда не
  добавляться в Git; если секрет уже попадал в историю, удаление файла новым
  коммитом недостаточно — секрет необходимо отозвать и очистить историю;
- перед коммитом запускайте `python scripts/check_secrets.py --mode staged`;
  CI повторяет проверку для всех отслеживаемых файлов; локальный hook можно
  включить командами `pip install pre-commit` и `pre-commit install`;
- используйте ID для категорий и ролей доступа: при заданном ID совпадение имени не даёт полномочий;
- не выводите token в консоль и отчёты;
- не публикуйте PostgreSQL `5432` в интернет; для PyCharm используйте SSH-туннель;
- не запускайте два экземпляра бота с одним Discord token;
- денежные операции, бронирования, заявки и назначения выполняются в PostgreSQL-транзакциях; поддерживаемые межсистемные сценарии дополнительно защищены receipt/outbox и идемпотентностью;
- загрузки Help ограничены типом, размером, частотой и числом одновременно обрабатываемых запросов;
- проверяйте иерархию ролей перед включением магазина или Showdown;
- резервируйте PostgreSQL, `.env`, `bot_config.toml` и `SHOWDOWN_STATE_PATH`;
- регулярно просматривайте `📩・сс-логи`, `🚗・авто-логи` и `📎・рекрутинг-логи`.

Публичная копия рабочего репозитория: история изменений осталась в приватной версии.
